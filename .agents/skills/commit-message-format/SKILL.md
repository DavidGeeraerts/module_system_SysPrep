# Commit message format
When you commit a change, you should write a commit message that describes what you changed and why. A good commit message helps others understand the history of the project and makes it easier to review changes.
- `Added` for new features.
- `Changed` for changes in existing functionality.
- `Fixed` for any bug fixes.
- `Removed` for now removed features.
- `Security` in case of vulnerabilities.
- `Deprecated` for soon-to-be removed features.
